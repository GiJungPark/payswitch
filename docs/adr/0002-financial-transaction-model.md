# ADR 0002: 결제와 개별 금융거래 분리

[ADR 목록](README.md) · [문서 홈](../README.md) · [프로젝트 홈](../../README.md)

- 상태: Accepted
- 날짜: 2026-09-13

## Context

결제 하나에는 승인, 여러 부분 취소와 망취소가 존재할 수 있다. 결제 요약에 상태 하나만 두면 원승인은 성공했지만 취소 결과는 불확실한 상황이나 서로 다른 취소 요청의 멱등성을 표현할 수 없다.

## Decision

- `Payment`는 승인 금액, 확정 취소 금액, 예약 취소 금액과 전체 요약 상태를 관리한다.
- 승인, 취소와 망취소는 각각 독립된 `FinancialTransaction`으로 생성한다.
- 취소와 망취소는 `originalTransactionId`로 대상 거래를 참조한다.
- 각 금융거래는 독립된 멱등키, 요청 hash와 상태를 가진다.
- 실제 전문 송수신 시도는 `InstitutionMessageAttempt`로 분리한다.
- 결과가 불확실한 취소 금액은 확정 전까지 `reservedCancelAmount`로 예약한다.

## Consequences

- 결제 요약과 개별 거래 상태를 함께 조회해야 한다.
- 테이블과 상태 전이 수가 늘어난다.
- 부분 취소 동시성과 취소 timeout을 명시적으로 표현할 수 있다.
- 전문 재시도 이력과 업무 거래 중복 여부를 분리해 분석할 수 있다.
