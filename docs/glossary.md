# 용어집

| 용어 | 설명 |
|---|---|
| PG | 가맹점과 금융기관 사이에서 결제 승인, 취소, 정산 등의 처리를 중계하는 시스템 또는 사업자다. |
| VAN | 가맹점 단말과 카드사·매입사 사이의 승인 전문을 중계하는 부가통신사업자다. 이 프로젝트에서는 외부 연동 기관의 한 종류로 단순화한다. |
| 전문 | 기관 사이에 주고받는 정해진 형식의 메시지다. 필드 위치와 byte 길이, padding, encoding 등을 계약으로 정의한다. |
| 승인 | 기관이 해당 결제 거래를 수락하고 승인번호를 부여하는 처리다. |
| 취소 | 성공한 원거래의 전부 또는 일부를 취소하는 별도 금융거래다. |
| 망취소/Reversal | 승인 결과를 확정하지 못했을 때 기관에 원거래의 원복을 요청하는 별도 거래다. 실제 동작은 기관 계약에 따라 다르다. |
| 조회 전문 | 기관이 보유한 거래의 최종 상태를 확인하는 메시지다. |
| UNKNOWN | 요청을 기관에 전달했을 가능성은 있지만 확정 응답을 받지 못해 성공과 실패를 단정할 수 없는 상태다. |
| 정산 | 승인·취소·수수료·환율을 기준으로 가맹점 또는 기관에 지급할 금액을 계산하는 업무다. |
| 대사 | PG와 기관이 각각 보유한 거래 내역을 비교하여 누락, 중복, 금액 및 상태 불일치를 찾는 업무다. |
| 영업일 | 거래, 정산, 추적번호 유일성의 기준이 되는 기관 업무 날짜다. 자정 기준 날짜와 다를 수 있다. |
| 멱등키 | 같은 업무 요청이 반복되어도 하나의 금융거래만 생성되게 하는 요청 식별자다. |
| Outbox | 업무 상태 변경과 같은 DB 트랜잭션에 발행할 이벤트를 저장하여 commit 이후 안전하게 전달하는 패턴이다. |
| Inbox | consumer가 처리한 event ID를 기록하여 중복 전달을 안전하게 무시하는 패턴이다. |
| Bulkhead | 특정 기관의 장애가 전체 시스템 자원을 고갈시키지 않도록 connection과 동시 실행 자원을 기관별로 격리하는 방식이다. |
